# B64 按请求就绪推进流水线：实现与验证

已完成 B48 AR 迁移和五组调度对照。实验默认选择 **C：就绪16行提前交付＋剩余AR压紧缩批**；D 的真实重叠已验证，但逐请求首包额外收益未稳定复现。原生产配置保持。

## 最终保留方案的匹配复测

GPU1，同一进程/模型，预热5轮、30轮测量，基线与C交替颠倒执行顺序，使用相同64请求和seed。时延从请求进入到PCM回调交付。下表是各波次指标的P50；“逐请求首包”先在每波计算64请求中位数，再统计波次。

| 指标 | 原B64整批屏障 | C | 改善 |
|---|---:|---:|---:|
| 前16请求均收到首包 | 458.80 ms | 209.50 ms | 54.34% |
| 前32请求均收到首包 | 459.32 ms | 274.27 ms | 40.29% |
| 逐请求首包中位数 | 459.33 ms | 313.11 ms | 31.83% |
| 全部64请求收到首包 | 460.33 ms | 433.33 ms | 5.87% |

全批完成P95从 489.06ms 到 496.01ms；逐请求中位数的跨波次P95从 488.08ms 到 375.21ms。用户优先逐请求首包，不设置整批退化硬门槛。

## 重叠及选择证据

- Nsight两波：同CUDA context1，AR stream13和声学stream25，真实kernel区间并集重叠 56.17ms；AR↔CFM约28.95ms，AR↔Vocoder约7.05ms。此值不是应用节省，不能与其他等待时间相加。
- C/D另外30轮颠倒顺序复测，逐请求中位数均值：C356.34/D349.46ms；原五组作业C352.56/D365.54ms。方向不一致，未把D声明为稳定优于C。
- 声学高优先级(-1)再测30轮，C338.37/D345.03ms；没有改善逐请求首包。C的提前交付收益在主要匹配测量中成立，缩批有真实计算减量；C作为保守实验默认，D仍显式可用。

## B48迁移与正确性

- B48 Draft/Target保持源权重、alpha1.0校准、backend和BF16/FP32保护。level5/FULL/max tactics/aux0，engine/ONNX外部权重绑定校验通过。Inspector显示B48和B64的INT8-bearing层数一致：Target126，Draft18；这不是全模型INT8声明。
- 在真实48条prefix上执行Draft、Target及完整首包AR，同配方Torch数值审计有限值通过；误差完整保存在migration_b48，无新增固定L2门槛。
- 真实GPU在2轮后将48个非连续请求从64槽迁移到B48，逐项核验KV/token/接受历史/轮数/随机数，再继续到48请求就绪。
- 实际B64测试在第8轮已就绪超过32行，主要64→32→16，跳过48。B48已验收可用，没有将未使用的B48归因为测量收益。
- A/B相对基线，语音码与接受历史一致；A↔B、C↔D同一路径PCM和代码哈希逐项一致，最终C与先前C同seed重放一致。缩批跨形状的浮点/生成差异不作位相同声明；没有ASR/MOS结论。
- 1/15/17请求不足16行/尾组填充、取消、重放和清理通过；提前EOS交接/短PCM裁剪用明确标注的终止状态测试，C/D字节一致，不当作模型采样质量或性能样本。
- 34项CPU检查通过，包括非连续/两次迁移、EOS/RNG保存、无效及自映射拒绝、错误后阻止陈旧KV重试。主计算无AR/CFM/Vocoder回退、无残留请求；异常先join声学任务，再交给调用者清理。

## 使用边界与下一步

F310/P258首包profile，现两轮一次检查；达到16个兼容请求触发声学，最终不足16行padding。请求在检查点内按入组顺序排队。回调在owner线程发布；必须通过on_chunk实时送出，若只等待run_ready返回事件列表，应用仍会等整组完成。没有持续到达补槽、完整句子吞吐或完整句子质量验收。

本轮止于已约定的B64首包调度与五组验证，默认C保留。更细检查边界可能让48档更早参与，需要单独对照，不能从当前数据推断；原两轮检查策略保持。
