# 独立批次重叠检查结果

GPU1，同一进程/同一 CUDA context、两个独立 model stream。复用最佳 INT8 engine，不修改默认调度或量化。

确实可以重叠，且 B16 首包阶段有净收益。当前双份模型实验不推荐直接替换生产 B32。

每轮32个请求，预热5轮、测量30轮；时延从整组开始到最后一个请求首包PCM交付。

| 方式 | P50 ms | P95 ms |
|---|---:|---:|
| 一份B16，串行两组 | 269.32 | 282.54 |
| 双B16，并行两组 | 248.59 | 269.64 |
| 交替复测：B16串行（第二份模型驻留） | 281.54 | 299.30 |
| 交替复测：双B16并行 | 259.19 | 289.99 |
| 单B32参考 | 244.03 | 277.92 |

同B16比较，中位数改善 7.69%；控制驻留成本并交替复测，改善 7.94%。B32单独作业测得，不能作严格配对；其随机生成序列/AR工作量不同。

实际重叠证据：

- Nsight两轮中，两个bank计算stream为13/29，CUDA context均为1；实际跨bank kernel区间并集重叠 158.06 ms。
- 阶段按同线程NVTX中的CUDA launch归属，GPU start/end计算重叠；存在AR↔AR、CFM↔AR、CFM↔Vocoder等交叉。AR↔CFM约8.07ms，两轮合计，不能直接当应用节省。
- AR范围的cudaStreamSynchronize：bank0等待98.86ms，其间另一bank kernel执行59.69ms；bank1等待110.84ms，其间另一bank执行77.78ms。此时间与kernel重叠相交，不相加。

正确性和执行：

- 相同B16配置、输入、seed：每轮所有PCM哈希/语音码哈希/接受轮序列/轮数与串行逐项一致。并行和串行完整请求数、生成工作量相同。
- CFM/Vocoder均实际执行B16原生Graph；检查计数完整，无AR/CFM/Vocoder回退。每轮取消后sessions、active_rows、error_sessions为零；后续波次可重放。
- B32同输入/seed但960条PCM、语音码、接受序列均非位相同；不同batch引擎的生成行为不能作为位相同重叠验收。其现有引擎验收沿用原部署记录，本次只作实际服务参考。

成本与边界：

- 双B16重复模型权重/执行状态。测量后的框架全进程allocated约14.05GiB、reserved约16.19GiB；单B32约7.45GiB/9.39GiB。这些是PyTorch全进程统计，不是整卡峰值，也不应把两个bank各自报告重复相加。
- 当前首包控制器先等全批AR就绪，旧overlap_acoustics分支在此路径不生效。Pool的多进程并行派发与同CUDA context跨stream并行是不同实现；本实验未启用/修改系统MPS。
- `.item()`检查和输出event等待对本批仍必要；可让另一个独立bank推进，而不能删除自己的依赖。共享同一可写TRT执行context/KV/Graph缓冲不安全。
- 本次是首包、批次同时到达、随后取消的实验；尚未验收完整EOS、持续到达、公平性、长期双bank功耗或共享权重调度。生命周期功耗记录不能当持续服务功耗。

本次止于机制和收益检查：已证明重叠存在及B16局部净收益，但直接双模型方案没有显示优于B32的优势，且显存增加；保留实验入口，生产最佳配置保持。下一步若继续优化，优先在共享只读权重、独立可写状态的调度中测试受控交错，而不是直接把workers加倍。
